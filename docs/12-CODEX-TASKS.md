# 12. Codex 分阶段开发任务清单

## 1. 使用方法

- Codex 每次只接收一个任务或一个紧密相关的小任务组。
- 每次任务必须附带相关需求文档路径。
- Codex 必须先阅读现有代码和迁移，不得重建已完成模块。
- 每个任务提交：代码、迁移、测试、OpenAPI 更新、变更说明和验收结果。
- 未通过当前任务验收前，不进入下一任务。

## 2. 仓库和工程规范

### 2.1 分支

- `main`：生产稳定
- `develop`：集成
- `feature/XW-xxx-description`：任务分支

### 2.2 提交

使用清晰提交前缀：`feat/fix/test/docs/refactor/chore`。

### 2.3 代码规则

- 业务逻辑放 Service／Domain 层，不堆进 View。
- 数据查询封装对象所有权过滤。
- 外部 API 只通过适配器。
- 所有会扣额度的任务必须先实现幂等和结算测试。
- 不使用浮动依赖版本。

- 更改固定 GEO 评分权重

- 将网页端自动化检测加入 V1

## 16. 变更控制

需求变更必须：

1. 创建 `docs/changes/CHANGE-xxxx.md`。
2. 描述原因、影响模块、数据迁移、兼容和验收变化。
3. 产品负责人批准。
4. 更新所有受影响文档和 OpenAPI。
5. 再交给 Codex 实施。
