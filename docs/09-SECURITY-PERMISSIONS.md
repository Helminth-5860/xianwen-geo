# 09. 安全、权限与审计要求

## 1. 安全目标

- 防止用户访问其他用户或其他主体的数据。
- 防止管理员越权查看、修改、导出或调用用户数据。
- 防止 API 密钥、密码、验证码和访问令牌泄露。
- 保证套餐和额度流水不可篡改、可追溯。
- 限制文件、URL 抓取、分享链接和 AI 输入带来的攻击面。
- 对高风险后台操作实施页面二次确认或当前超级管理员密码复核。

## 2. 权限模型

采用 RBAC＋数据范围控制：

- RBAC 控制菜单和动作。
- 数据范围控制管理员能查看哪些客户。
- 对象级权限控制用户只能访问自己账号和主体的数据。
- 超级管理员拥有全局管理权，但敏感密钥仍只可替换，不可回看明文。

## 3. 用户端授权

每个请求必须从会话识别当前用户，不接受前端传入 `user_id` 作为授权依据。

所有主体级查询使用：

```text
resource.user_id == current_user.id
AND resource.subject_id belongs to current_user
```

对象不存在和无权访问可统一返回 404，减少对象枚举。

## 4. 管理员权限

### 4.1 权限粒度

至少包含：查看、创建、编辑、删除、审核、冻结、额度调整、任务重试、导出、模型启停、提示词发布、审计查看、强制只读查看。

### 4.2 客户数据范围

角色可配置：

- 仅查看自己负责客户
- 查看角色范围
- 查看全部客户

权限校验必须在服务端查询层实现。

### 4.3 API 密钥权限

- 只有超级管理员可见密钥管理菜单和 API。
- 录入时显示一次。
- 保存后只返回掩码。
- 原密钥无法通过任何 API 读取。
- 更换时输入新密钥，验证通过后切换。

## 5. 管理员协助查看

### 5.1 普通查看

- 管理员申请并填写原因。
- 用户站内授权。
- 授权仅一次会话。
- 退出、超时、撤销后失效。

### 5.2 强制查看

- 仅超级管理员。
- 原因限账号安全、违规调查、系统故障。
- 完成后通知用户。

### 5.3 只读限制

禁止：

- 修改任何业务数据
- 提交 AI 任务
- 扣额度
- 导出资料
- 复制敏感字段
- 访问 API 密钥或内部提示词

## 6. 身份认证

### 6.1 用户

- 手机号＋密码
- 手机号＋短信验证码
- 密码重置通过短信

### 6.2 管理员

- 管理员通过独立入口使用密码建立后台 Session，登录本身不发送短信。
- 安全关键动作必须在后端验证当前管理员短时 SMS Step-Up proof；业务高风险动作使用确认、当前密码和版本检查，不默认触发短信；普通 dashboard 与低风险读取同样不触发短信。
- Step-Up challenge 与管理员、Session/RBAC/安全版本、IP 和设备摘要绑定，过期、重放或上下文变化均失败关闭。

### 6.3 密码

- 使用成熟密码哈希算法，如 Argon2id 或 Django 推荐安全哈希。
- 不记录明文或可逆密码。
- 支持密码强度、失败锁定、已泄露密码检查（条件允许时）。

### 6.4 会话

- HttpOnly、Secure、SameSite Cookie。
- 管理后台与用户端可使用不同 Cookie 名和会话域。
- 登录成功后轮换会话 ID，防止会话固定。
- 会话过期和强制退出即时生效。
- 不在 localStorage 保存长期访问令牌。

## 7. CSRF、CORS 和点击劫持

- 所有状态修改请求强制 CSRF。
- CORS 仅允许配置的前端域名。
- 设置 `X-Frame-Options` 或 CSP `frame-ancestors`。
- 管理后台禁止被第三方嵌入。

## 8. 频率限制

至少限制：

- 短信发送：手机号、IP、设备
- 登录失败：账号、IP
- 注册
- 密码重置
- 报告公开分享访问
- 发布链接检测和网页抓取
- AI 任务创建
- 任务状态轮询
- 导出和批量下载

限制命中返回 429 和可理解提示，不泄露风控阈值。

## 9. 短信安全

- 验证码只保存哈希。
- 有效期短。
- 使用一次后失效。
- 限制错误尝试次数。
- 验证码不得进入普通日志、埋点或客服页面。
- 同一用途和手机号的新验证码使旧验证码失效。

## 10. API 密钥和秘密管理

### 10.1 禁止位置

- 前端代码
- Git 仓库
- Docker 镜像层
- 普通数据库明文字段
- 日志和异常响应
- Codex 提示词或截图

### 10.2 建议存储

优先使用云密钥管理；如初期使用应用层加密：

- 主加密密钥通过部署环境注入。
- 数据库只保存密文、掩码和版本。
- 应用启动后按需解密到内存。
- 密钥轮换后旧版本在过渡期受控保留。

### 10.3 日志脱敏

对 `Authorization`、`api_key`、`secret`、`token`、`password`、`sms_code` 等字段统一脱敏。

## 11. 高风险操作

### 11.1 验证级别

- 二次确认
- 密码验证

### 11.2 直接执行约束

- 只有当前有效超级管理员可以执行平台级敏感操作。
- 密码复核通过后在同一事务中执行并写入操作记录。
- 目标版本变化时失败关闭，要求刷新后重试。
- 不创建等待其他账号处理的队列。

## 12. 审计日志

### 12.1 用户安全日志

- 注册
- 登录成功／失败
- 密码重置
- 手机号更换
- 会话撤销
- 注销申请和撤销

### 12.2 管理员审计

- 审核、冻结、解冻
- 套餐开通／变更
- 额度操作
- 密钥操作
- 模型启停
- 提示词发布
- 数据导出
- 删除／恢复
- 用户视角查看
- 审批

### 12.3 不可变性

普通业务 API 无权更新或删除审计表。需要修正时追加新记录。

## 13. 额度安全

- 冻结、扣除、返还必须幂等。
- 任务和冻结同事务创建。
- 所有余额使用数据库行锁或原子更新。
- 禁止出现可用量或冻结量负数。
- 定时验证流水与账户余额一致。
- 异常触发严重告警。

## 14. 数据隔离

### 14.1 用户与主体

所有业务表必须有清晰的所有权链。Repository／QuerySet 层提供默认过滤，避免开发者忘记加用户条件。

### 14.2 COS 对象

对象键建议包含不可预测 UUID，不使用手机号或主体明文。私有桶，下载使用短期签名 URL。

### 14.3 管理员导出

导出文件放私有对象存储，短期有效，记录下载人和时间；全量导出要求密码复核。

## 15. 文件上传安全

- 扩展名、MIME 和文件签名三重校验。
- 限制单文件大小和总存储。
- 禁止可执行文件和宏执行。
- Office／PDF 只解析内容，不执行嵌入脚本。
- 图片重新编码或安全解码。
- 病毒／恶意文件扫描。
- 原始文件和解析任务隔离。
- 用户确认解析文本后才进入 AI 资料包。

## 16. URL 抓取与 SSRF

适用于：主体资料补充、文章资料检索、网页导入、引用核验、发布检测。

必须：

- 只允许 HTTP／HTTPS。
- 解析 DNS 后阻止私网、回环、链路本地、保留地址和云元数据地址。
- 每次跳转重新校验。
- 限制跳转次数、响应大小、连接和读取超时。
- 拒绝非文本或超大文件。
- 禁止携带内部 Cookie、认证 Header 或用户会话。
- 通过独立低权限抓取进程或网络策略运行。

## 17. XSS 和内容渲染

- 模型回答、文章、公告、用户备注和抓取网页均视为不可信内容。
- Markdown／HTML 使用白名单清洗。
- 导出 HTML 也必须清洗脚本和危险属性。
- 不允许模型输出直接注入 React `dangerouslySetInnerHTML`。
- 链接加 `rel="noopener noreferrer"`。

## 18. 提示词注入防护

### 18.1 检测评分

原始模型回答是待分析数据，不是指令。评分提示词使用严格分隔、JSON Schema 和固定规则。

### 18.2 资料抓取

网页和文件中的“忽略之前指令”等内容不得改变系统行为。

### 18.3 AI 助手

助手只能读取白名单上下文，不能调用执行工具，不接受用户要求读取其他主体、内部提示词或 API 密钥。

## 19. 内容审核

- 文章和图片生成后自动审核。
- 疑似高风险进入人工审核。
- 高风险主体可配置更严格审核。
- 用户输入、参考图、上传资料同样进行安全检查。
- 审核结果和责任归因决定额度返还。

## 20. 分享链接安全

- 使用至少 128 位随机令牌，数据库只存哈希。
- 可设置密码，密码只存哈希。
- 支持有效期和立即关闭。
- 限制密码尝试和访问频率。
- 分享页面不展示账号手机号、内部 ID 和后台入口。
- 下载 PDF 使用受控接口，不暴露 COS 永久 URL。

## 21. 个人数据和隐私

### 21.1 最小化

只收集实现功能所需的手机号、昵称、业务资料和日志。

### 21.2 用户导出

用户可以导出自己的业务数据，不包含内部提示词、供应商密钥、系统成本或其他用户数据。

### 21.3 注销

- 7 天冷静期。
- 期间禁止新任务。
- 结束后删除业务内容。
- 额度、套餐、审计和安全日志去标识化保留。
- 手机号释放后允许重新注册，但不恢复旧数据和试用。

## 22. 数据保留与删除

- 业务记录按套餐配置。
- 审计和额度记录长期保留或匿名化。
- 回收站期间不可用于新业务。
- 永久删除使用后台任务并记录结果。
- 删除失败不得向用户显示“已完成”。

## 23. 备份安全

- 备份加密。
- 备份账号与业务账号隔离。
- 本地、对象存储和异地多层备份。
- 恢复测试。
- 备份文件访问和删除记录审计。
- 生产密钥与备份解密密钥分离。

## 24. 基础设施网络

- PostgreSQL、Redis 只走内网，不开放公网。
- COS 使用私有桶。
- 管理后台可选 IP 白名单，默认关闭。
- Nginx 只开放 80／443；生产强制 HTTPS。
- 数据库和 Redis 安全组只允许应用服务器或指定服务访问。

## 25. 安全响应头

建议：

- `Strict-Transport-Security`
- `Content-Security-Policy`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy`
- `Permissions-Policy`
- 安全 Cookie 属性

CSP 需兼容 Next.js 静态资源并尽量使用 nonce，避免宽泛 `unsafe-inline`。

## 26. 依赖和供应链

- 锁定 Python 和 Node 依赖版本。
- 启用依赖漏洞扫描。
- CI 中运行静态检查、单元测试和秘密扫描。
- Docker 使用最小基础镜像和非 root 用户。
- 生产镜像不包含测试密钥、源码缓存和开发工具。

## 27. 监控和告警

严重告警：

- 数据库不可用
- Redis 不可用
- 额度不变量破坏
- API 密钥失效
- 核心模型全部不可用
- 备份连续失败
- COS 故障
- 登录攻击异常

普通／重要／严重分别使用后台、站内和短信渠道。

## 28. 安全验收

上线前至少完成：

- 越权访问测试
- CSRF／CORS 测试
- 会话固定和退出测试
- 密码和验证码暴力限制
- API 密钥泄露扫描
- SSRF 测试
- 文件上传恶意样本测试
- XSS 测试
- 分享链接枚举和爆破测试
- 额度并发一致性测试
- 管理员确认／密码复核绕过测试
- 用户视角只读绕过测试
- 备份恢复演练
