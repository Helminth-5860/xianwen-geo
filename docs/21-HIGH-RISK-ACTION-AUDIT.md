# 高风险操作与操作记录

## 当前策略

全平台只有一个超级管理员。所有风险动作只支持两种保护方式：

- `confirm`：页面展示二次确认，调用方必须传入 `confirmed=true`。
- `password`：页面要求重新输入当前超级管理员密码，密码只存在于调用栈。

确认后直接执行；密码模式在密码校验通过后也在原请求中直接执行。操作完成后写入 AuditEvent，供产品
“操作记录”页面查询。失败同样记录稳定错误码和安全摘要。密码、验证码、Cookie、Session、
完整手机号、完整 IP、API Key、基础设施密钥和原始异常不会进入操作记录。

安全关键动作现有的短信 Step-Up 是对同一超级管理员身份的再次验证，不是其他账号授权。
普通套餐、订阅等日常业务动作只使用页面二次确认。

## 已删除能力

- 不存在待处理队列、第二管理员决定或等待批准状态。
- 原高风险审批 API 与后台页面已删除。
- 风险目录和策略只允许 `confirm`、`password`。
- 后台只保留“操作记录”和“系统设置”。
- OpenAPI 不再声明等待队列路径、202 响应或相关请求结构。
- 当前数据库结构不再包含审批队列表或审批外键。

## 数据迁移

`admin_rbac.0024_retire_multi_admin_approval` 执行以下前向变更：

1. 删除旧菜单和动作权限及其角色关联；
2. 将旧风险动作和策略映射为 `confirm` 或 `password`；
3. 待处理记录在迁移时统一取消，并写入稳定退役原因；
4. 更新数据库约束，阻止再次写入旧模式。

后续 forward migration 依次移除套餐续费排期和风险目录发布的数据库级队列绑定、关联字段与
队列表。删表前将必要的历史状态和安全摘要写入操作记录，已有数据库可按迁移图安全升级。
这些变更不改变套餐、额度、风险目录或正常业务审核流程的核心数据语义。

## 执行和记录边界

风险动作通过编译期静态 Handler 注册表执行；数据库字段不能动态触发 URL、SQL、Shell、
Celery 名称或任意 callable。执行前继续校验权限、对象范围、乐观版本、CSRF、确认状态以及必要
的密码或 Step-Up。执行成功和 `AuditEvent` 写入处于同一事务边界；写操作记录失败时业务操作
整体回滚。

本次变更不修改 Provider、Execution、Scoring 或 quota ledger 的核心语义，也不删除历史数据。
