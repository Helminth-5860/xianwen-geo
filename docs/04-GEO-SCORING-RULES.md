# 04. GEO 检测与评分规则 V1

## 1. 规则目标

本文件定义显问 GEO 检测的统一评分口径。任何页面、报告、API、数据库和测试不得自行创建另一套分数逻辑。

评分规则采用版本管理。V1 规则标识建议：`geo_score_v1`。

## 2. 核心术语

| 术语 | 定义 |
|---|---|
| 检测点 | 1 个问题在 1 个模型中调用 1 次 |
| 单题单模型结果 | 某问题在某模型中的原始回答、引用和六维评分 |
| 模型得分 | 某模型对本次全部有效问题的平均得分 |
| GEO 综合得分 | 正式模型得分的等权平均 |
| 品牌认知与口碑得分 | 品牌指向型问题的独立评分，不计入 GEO 综合分 |
| 曝光潜力指数 | 提及率、推荐率、排名和模型覆盖的辅助指数 |
| 正式得分 | 达到规定成功率和模型数量门槛的得分 |
| 临时参考分 | 数据量不足时展示但不进入正式趋势的分数 |

## 3. 问题类型

### 3.1 自然探索型问题

问题未直接出现或明确指向当前主体的：

- 主体完整名称
- 已确认简称／别名／英文名
- 可唯一识别且已确认计入主体提及的产品名

该类问题用于衡量主体能否被模型自然发现和推荐，采用完整六维评分，计入 GEO 综合得分。

### 3.2 品牌指向型问题

问题直接包含或明确指向主体名称、别名、英文名或唯一产品名，例如“某品牌怎么样”。

该类问题不计算“主体提及”和“出现排名”，单独计入品牌认知与口碑得分。

### 3.3 判定方式

1. 程序匹配有效名称和唯一产品清单。
2. DeepSeek 辅助判断语义指向。
3. 用户在问题库确认阶段可修改。
4. 检测开始后以快照中的问题类型为准。

## 4. 主体提及判定

### 4.1 有效名称清单

主体版本必须维护：

- 主体完整名称
- 品牌名称
- 用户确认的简称
- 英文名
- 历史名称或常用别名

### 4.2 产品提及

仅提到产品名时，只有同时满足以下条件才视为主体提及：

- 产品已录入主体资料并经用户确认。
- 产品能唯一对应当前主体。
- 产品配置为“计入主体提及”。

通用产品词、重名产品或无法唯一指向主体的词不计入。

### 4.3 未提及处理

自然探索型问题中，若主体未被明确有效提及：

- 单题单模型总分直接为 0。
- 推荐、排名、准确度、倾向和引用不再继续计算。
- 模型正常返回但未提及属于有效 0 分，不是调用失败。

## 5. 六维评分

自然探索型问题单题满分 100 分：

| 维度 | 权重 |
|---|---:|
| 主体提及 | 25% |
| 推荐程度 | 20% |
| 出现排名 | 15% |
| 信息准确度 | 20% |
| 正负倾向 | 10% |
| 引用来源 | 10% |

公式：

```text
single_question_score =
mention_score × 0.25
+ recommendation_score × 0.20
+ ranking_score × 0.15
+ accuracy_score × 0.20
+ sentiment_score × 0.10
+ citation_score × 0.10
```

所有分项为 0–100。最终分数保留至少 4 位小数存储，页面展示 1–2 位小数。

## 6. 主体提及得分

自然探索型问题：

- 有效提及：100 分
- 未提及：0 分，并触发整题总分为 0

不得使用模糊语义推测将未明确出现的主体判为提及。

## 7. 推荐程度得分

| 判定 | 分数 |
|---|---:|
| 强烈推荐、首选、最佳选择 | 100 |
| 明确列入推荐名单 | 75 |
| 可选方案、中性介绍、仅客观说明 | 40 |
| 明确不推荐、负面劝退 | 0 |

规则：

- 没有明确推荐态度不得给 75 分。
- 同时有正负观点时以最终结论为主。
- 保存判定依据的原文片段。

## 8. 出现排名得分

| 出现位置 | 分数 |
|---|---:|
| 第 1 名 | 100 |
| 第 2–3 名 | 80 |
| 第 4–5 名 | 60 |
| 第 6–10 名 | 40 |
| 第 10 名以后 | 20 |
| 未进入推荐名单，仅正文提及 | 10 |

规则：

- 以主体首次有效出现位置为准。
- 无编号但有明显先后顺序时按正文顺序。
- 只在脚注、引用来源或免责声明中出现，不计正文排名。
- 同一主体多次出现不重复累计。
- 唯一产品提及按产品对应主体的位置。

## 9. 信息准确度得分

| 判定 | 分数 |
|---|---:|
| 关键信息完全准确 | 100 |
| 大部分准确，仅轻微偏差 | 75 |
| 部分准确，但有明显错误或过时信息 | 40 |
| 核心信息错误或主体混淆 | 0 |

基准：本次检测快照绑定的已确认主体资料版本。

系统保存：错误内容、正确资料、资料字段和证据片段。

## 10. 正负倾向得分

| 判定 | 分数 |
|---|---:|
| 强烈正面、明显赞扬 | 100 |
| 明确正面评价 | 75 |
| 中性介绍或正负并存 | 50 |
| 明确负面评价 | 25 |
| 强烈负面、劝退或风险警告 | 0 |

规则：

- 无明显态度时按 50。
- 同时有正负内容时以最终结论为主。
- 涉及欺诈、违法、严重安全或质量警告时按 0。
- 保存判定依据原文。

## 11. 引用来源得分

| 来源 | 分数 |
|---|---:|
| 主体官网、政府、权威行业机构 | 100 |
| 主流媒体、权威垂直平台 | 80 |
| 一般自媒体或普通网站 | 50 |
| 有来源但无法访问或核验 | 20 |
| 无引用来源 | 0 |

### 11.1 有效引用来源

- API 返回结构化引用链接。
- 回答正文出现明确可核验网址。
- 回答正文明确写出可识别来源名称。

“有资料显示”“据报道”等模糊表述不计有效引用。

### 11.2 多来源

V1 单题引用维度按最高质量有效来源评分，同时保存全部来源。来源内容与主体无关时不计。

### 11.3 核验状态

- 已访问且相关
- 可访问但不相关
- 无法访问
- 来源名称可识别但无链接
- 失效链接

## 12. 品牌认知与口碑评分

品牌指向型问题不计算主体提及和出现排名。其余原权重按比例放大：

| 维度 | 权重 |
|---|---:|
| 推荐程度 | 33.333333% |
| 信息准确度 | 33.333333% |
| 正负倾向 | 16.666667% |
| 引用来源 | 16.666667% |

公式：

```text
brand_question_score =
recommendation_score × 1/3
+ accuracy_score × 1/3
+ sentiment_score × 1/6
+ citation_score × 1/6
```

主体提及和出现排名标记为 `N/A`，不得记 0 或 100。

品牌口碑分与 GEO 综合分完全分开展示和统计。

## 13. 程序规则与 AI 语义判断

### 13.1 程序优先

- 主体名称、别名和唯一产品匹配
- 主体首次出现位置
- 编号／列表顺序
- 引用 URL 提取
- 来源访问状态

### 13.2 DeepSeek 判断

- 推荐程度
- 信息准确度
- 正负倾向
- 无明确结构时的排名辅助识别
- 来源名称分类
- 竞品实体识别和同义名称合并

### 13.3 最终规则

- 不设置人工改分。
- 不设置待复核或人工评分流程。
- DeepSeek 直接给出最终语义判断和依据。
- 程序按固定权重计算最终分数。
- 历史报告不可修改。
- 用户如认为结果不准确，只能重新检测。

## 14. 单个模型得分

### 14.1 计算范围

同一模型内：

```text
model_score = 成功检测的问题得分之和 ÷ 成功检测问题数量
```

- 所有问题等权。
- 模型正常返回但未提及主体：0 分计入。
- API 调用失败、超时、取消：不计入分母，并返还检测点。
- 自然探索型问题和品牌指向型问题分别计算模型 GEO 分与模型口碑分。

### 14.2 正式门槛

模型对该类问题的调用成功率达到 80%：正式模型得分。

成功率：

```text
success_rate = 成功返回的该类问题数 ÷ 计划检测的该类问题数
```

- 成功率 ≥ 80%：正式模型分。
- 成功率 < 80%：临时参考分。
- 临时参考分不参与正式综合分。

若某类问题数为 0，则不生成该类模型分。

## 15. 综合得分

### 15.1 GEO 综合得分

取成功产生的正式模型 GEO 得分等权平均：

```text
geo_overall_score = Σ正式模型GEO得分 ÷ 正式模型数量
```

### 15.2 品牌认知与口碑综合分

取成功产生的正式模型口碑得分等权平均：

```text
brand_overall_score = Σ正式模型口碑得分 ÷ 正式模型数量
```

### 15.3 正式门槛

- 6–8 个正式模型得分：正式综合分。
- 1–5 个正式模型得分：临时参考分。
- 0 个：该类检测失败。

失败模型不按 0 分计入综合分。

## 16. GEO 分数等级

| 分数 | 等级 |
|---|---|
| 90–100 | 卓越 |
| 75–89.99 | 优秀 |
| 60–74.99 | 一般 |
| 40–59.99 | 较弱 |
| 0–39.99 | 薄弱 |

模型分、GEO 综合分和品牌口碑分使用同一等级表，但在页面上明确指标名称。

## 17. 曝光潜力指数

### 17.1 定义

曝光潜力指数是系统评估指数，不是实际曝光人数。页面必须展示该免责声明。

### 17.2 公式

```text
exposure_index =
mention_rate_score × 0.40
+ recommendation_rate_score × 0.25
+ ranking_performance_score × 0.20
+ model_coverage_score × 0.15
```

四项均标准化到 0–100。

### 17.3 子项定义

#### 主体提及率

自然探索型的成功调用中，有效提及主体的比例：

```text
mention_rate_score = 有效提及数量 ÷ 自然探索型成功调用数量 × 100
```

#### 推荐率

自然探索型成功调用中，推荐程度得分达到 75 或 100 的比例：

```text
recommendation_rate_score = 明确推荐数量 ÷ 已提及且成功调用数量 × 100
```

若已提及数量为 0，得分为 0。

#### 排名表现

所有已提及自然探索型结果的排名得分平均值；未提及结果按 0 参与曝光排名表现，以避免高估：

```text
ranking_performance_score = Σ每次调用排名曝光分 ÷ 自然探索型成功调用数量
```

其中未提及时排名曝光分为 0。

#### 模型覆盖率

本次选择并成功完成检测的模型中，至少在一个自然探索型问题提及主体的模型比例：

```text
model_coverage_score = 提及主体的成功模型数 ÷ 本次成功模型数 × 100
```

### 17.4 计算范围与可比性

- 以本次选择并成功检测的模型为范围。
- 至少 6 个正式模型 GEO 分时才生成正式曝光指数。
- 少于 6 个时显示临时参考指数。
- 只有模型组合一致时允许历史趋势比较。

### 17.5 等级

| 指数 | 等级 |
|---|---|
| 90–100 | 极高 |
| 75–89.99 | 高 |
| 60–74.99 | 中 |
| 40–59.99 | 较低 |
| 0–39.99 | 低 |

## 18. 竞品曝光参考

### 18.1 数据来源

仅从同一份模型原始回答中自动识别其他品牌、企业或产品，不额外调用模型，不额外扣检测点。

### 18.2 指标

- 竞品标准名称
- 别名合并结果
- 提及次数
- 首次出现排名
- 推荐状态
- 当前主体与竞品排名差距
- 出现的问题和模型

### 18.3 限制

- 不生成竞品完整 GEO 得分。
- 页面标注“竞品曝光参考”。
- 用户可将误识别项标记为非竞品。
- 行业词、平台名和通用产品词不得判为竞品。

## 19. 历史趋势与可比性

### 19.1 正式涨跌条件

以下两项必须完全一致：

- 实际问题列表
- 模型组合

满足时可计算：总分涨跌、模型涨跌、六维变化、曝光指数变化。

### 19.2 主体资料变化

主体资料版本可以不同，但必须标注“主体资料版本已变化”，并允许查看前后资料摘要。

### 19.3 不可比情况

问题或模型组合不同：只允许并排展示，不计算环比、涨跌或趋势连接线。

### 19.4 规则版本变化

评分规则版本变化时，即使问题和模型一致，也应显示“评分规则版本变化”，默认不计算正式涨跌，除非未来实现同规则重算。V1 不重算历史报告。

## 20. 模型联网与降级

每条模型调用记录：

- 是否请求联网
- 是否实际联网
- 是否降级
- 降级策略
- 降级结果是否参与评分

模型后台可配置：

1. 降级并参与评分
2. 降级但只作为临时参考
3. 直接失败并退款
4. 连续异常后暂停模型

报告必须标注实际模式。

## 21. 失败与退款

- API 失败、超时、系统取消：调用失败，不计分，返还检测点。
- 正常回答但没有主体：成功调用，计 0 分，扣检测点。
- 模型被暂停且尚未调用：取消并返还。
- 用户取消等待任务：返还未开始调用的检测点。
- 部分成功：按实际成功数量扣点。

## 22. 原始证据与展示

每条调用保存：

- 原始问题
- 模型名称、模型 ID 和版本
- 检测时间
- 联网状态
- 完整原始回答
- 关键证据片段
- 引用来源
- 程序提取结果
- DeepSeek 判定结果和依据
- 六维分数

前端默认展示关键片段，用户点击展开完整原始回答。

不得：

- 伪装为 AI 官网截图
- 生成大量逐条证据卡片
- 只保存摘要而丢失原始回答

## 23. 评分模型版本

- 使用固定 DeepSeek 模型版本进行语义评分。
- 模型升级时创建新评分引擎版本。
- 新版本只影响新检测。
- 历史报告保持原结果。
- 每份报告保存：评分模型 ID、参数、提示词版本、规则版本。

## 25. 测试基准

必须准备固定测试样本覆盖：

- 完全未提及主体
- 只提及别名
- 只提及唯一产品
- 重名产品不应计入
- 主体排第 1／3／7／正文提及
- 强烈推荐、普通推荐、中性和劝退
- 信息完全准确、轻微偏差、明显错误、主体混淆
- 强正面、中性、负面、风险警告
- 官方、政府、主流媒体、普通网站、失效来源和无引用
- 品牌指向型问题
- 模型调用失败与正常 0 分的区别
- 80% 模型成功率边界
- 6 个正式模型边界
- 不同问题／模型组合不计算涨跌
