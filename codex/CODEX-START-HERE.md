# Codex 开发起始指令

你正在开发“显问 GEO 智能体系统 V1”。在修改任何代码前，必须完成以下动作：

1. 阅读仓库 `README.md`。
2. 阅读当前任务引用的需求文档。
3. 阅读 `docs/04-GEO-SCORING-RULES.md`、`docs/05-QUOTA-BILLING-RULES.md` 和 `docs/09-SECURITY-PERMISSIONS.md` 中与任务相关的部分。
4. 检查现有代码、测试、迁移和 OpenAPI，不得重复创建相同模型或端点。
5. 输出实施计划，经确认或在任务明确授权后再修改代码。

## 不可更改的产品约束

- V1 不做视频。
- 不做在线支付或线下收款记录。
- 不做第三方 AI 网页端自动化。
- 固定 8 个检测模型。
- 管理员不能人工改 GEO 分数。
- 失败模型不按 0 计入综合分。
- 模型正式分门槛为问题成功率 80%。
- 综合正式分门槛为至少 6 个正式模型。
- 检测点为 1 问题 × 1 模型 × 1 次。
- 所有额度变化必须通过不可变流水。
- 文章优化后二选一，只保留用户选择稿，不建立文章版本历史。
- AI 助手不保存聊天，不执行任务。
- 所有界面使用简体中文。

## 代码设计要求

- 模块化单体。
- Django Service／Domain 层承载业务逻辑。
- 外部 AI 通过统一适配器。
- 长任务通过 Celery。
- PostgreSQL 是永久事实来源；Redis 不保存唯一业务事实。
- 所有扣额度 POST 支持幂等键。
- 对象级权限服务端校验。
- API 密钥不得进入前端、Git 或日志。

## 每次任务完成时必须报告

- 修改文件
- 数据迁移
- API 和 OpenAPI
- 权限
- 额度与回滚
- 测试和执行结果
- 手工验收步骤
- 已知限制

从 `docs/12-CODEX-TASKS.md` 按任务编号顺序实施，不要一次性生成整个系统。
