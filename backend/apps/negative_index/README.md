# 公开负面风险指数 V1

## 产品口径

负面信息指数用于发现当前主体在公开网络中的可发现负面风险信号，并以 0–100 分表示当前公开风险暴露，**分数越高风险越高**。

该指数是风险情报分析，不是司法或监管事实认定。未经权威确认的投诉、质疑、观点和传闻必须保留其证据性质，不得改写为已证实事实。

## 数据来源

- 与信源指数共用百度 Search V2 Standard 搜索发现能力、URL 规范化、主体相关度、来源分类、搜索可见度和新鲜度。
- 使用主体正式名称、品牌/别名构建 8–12 个负面专项 Query。
- 搜索请求通过共享短期缓存复用，避免同 Query 在信源指数和负面指数间重复计费。
- V1 不接微博/小红书/抖音实时流，不宣称覆盖整个互联网。

## 分析流程

1. 百度公开搜索元数据召回。
2. 规则只做低成本候选初筛，不直接判定事实。
3. 已配置的结构化 AI 适配器判断主体相关性、负面置信度、类别、严重度、证据性质和事件状态。
4. 高风险且证据不足的候选，按需使用现有安全 Web Fetch/Parser 抽取有限正文证据窗口后二次判断；不持久化完整网页正文。
5. 相同事件的转载/重复报道先聚类，再计算风险，避免转载量刷高指数。
6. AI 只输出结构化特征，最终事件风险和总指数由确定性公式计算。

## 事件类别

- 监管处罚
- 司法风险
- 消费者投诉
- 产品/服务事故
- 经营风险
- 媒体负面
- 网络舆情
- 其他

## 证据性质

- 官方结论
- 媒体事实报道
- 媒体转述指控
- 用户指控
- 观点
- 传闻
- 回应/澄清

回应、澄清、辟谣不能因为包含“诈骗/处罚”等负面词就被当成已证实负面事实。

## 指数

单事件先结合严重度、证据可信度、搜索可见度、新鲜度和事件状态计算当前风险。企业总指数只聚合风险最高的前 10 个有效事件并采用饱和模型，防止大量低质量帖子把指数刷满。

`retracted` 和 `false_positive` 事件风险为 0；`resolved`、`disputed`、`suspected` 会按状态降低当前风险。
